## 依赖与体积

新增 `papaparse`、`yaml`、`pica` 三个有明确用途的依赖，移除 `nerdamer-prime` 及其专用间接依赖。未增加 UI 框架。PDF 使用已有依赖，pica 只在栅格图像执行缩放时加载。

同一工作区生产构建中，公式计算器的 JavaScript 分块从 **974.79 KB／gzip 349.31 KB** 降至约 **40.2 KB／gzip 12.8 KB**。该数据仅指计算器分块，不是整个站点缩减比例；新增计算器样式约 3.2 KB。PDF 编辑器、HEIC 和模型功能仍有较大的按需资源。

## 行为边界

- 页面编排按最终页计划复制 PDF 页面，不先栅格化。原目录不会自动迁移；可按来源创建新书签。
- 交互表单会将当前外观固定到输出页，输出字段不可继续编辑；源文件保持可重复使用。数字签名效力不保留。其他文档级结构、复杂批注和附件未承诺完整迁移。
- 加密 PDF 导入会明确失败，当前不提供密码解锁流程；损坏文件会按名称提示，其他可读文件仍可导入。
- 取消导入保留已成功读入的来源；取消导出不提供部分 PDF。浏览器无法在同一个同步库调用中即时中断，取消会在异步检查点生效。
- 本次没有把所有 134 个工具替换为第三方完整版。OCR、复杂 PDF → EPUB、媒体统一时间线、服务端高级转换与超大文件持久化仍按原矩阵的后续优先级推进。
- 浏览器入口巡检覆盖全部工具，不等于所有大型媒体格式、模型下载和加密 PDF 的全面兼容性认证。

## 验证入口

```bash
npm run typecheck
npm run i18n:check
npm run test:run
npm run build
npm run test:workbench
```

新增功能回归位于 `tests/tool-upgrades.spec.ts`；既有 `tests/tool-experiences.spec.ts` 继续检查缩放实际输出等能力。测试使用本机 Chrome 时设置 `PLAYWRIGHT_CHANNEL=chrome`。

最终验证结果：

- 类型检查、生产构建、中文／英文语言资源检查通过（2712 个匹配键）。
- 82 个单元测试文件、757 项测试通过。
- 31 项工作台浏览器测试通过，其中入口巡检遍历全部 134 个工具的桌面与手机布局。
- 6 项原有 Chromium 端到端测试通过。
- 开发服务 `/pdf/merge-pdf` 返回 200，上传文件后可正常显示 Canvas 预览，无页面运行时错误。
- 已目视检查 PDF 页面模式、手机布局、英文深色平板布局及计算器结果；修正了平板导出区出现隐式第三列和长数字折行的问题。

此阶段修改的 TypeScript 文件通过 ESLint。当时全仓库另有 32 个既有错误、85 个警告；后续已在[界面简化与问题修复](../interface-simplification.md)中全部清理，当前为 0 错误、0 警告。
